# Оркестрація (ПР6)

## Задача для оркестрації
Нова функціональність: **нагадування про ревакцинацію** – модуль `core/reminders.py`, що повертає вакцинації, термін яких настає протягом найближчих N днів. Задача достатньо складна: потрібні знання предметної області (vault), вибір шару, код, тести й незалежна перевірка.

## Ролі
| Роль | Відповідальність | Доступ |
|------|------------------|--------|
| Planner | розбиває задачу на кроки, звіряється з vault і архітектурою; код не пише | vault (через MCP-клієнт), код лише читання |
| Coder | реалізує код і тести за планом, запускає `pytest`/`ruff` | handoff, guardrails, skill `gen-unit-tests`, запис файлів у межах плану |
| Reviewer | перевіряє результат на відповідність плану, ADR і guardrails, повертає на доопрацювання | handoff обох ролей, код лише читання, запуск тестів |

Визначення ролей: `.claude/agents/*.md`.

## Handoff
Між ролями передається не лише результат, а й обґрунтування. Формат у `orchestration/handoff-template.md`: задача, що зроблено, **рішення та обґрунтування**, використані джерела, ризики й відкриті питання, доручення наступній ролі.

## Технічна реалізація
Механізм: послідовні сесії з рольовими інструкціями. Координатор (Claude Code) запускає кожну роль як окремого субагента з чистим контекстом, у промпті якого вказано прочитати файл ролі (`.claude/agents/<роль>.md`) та handoff попередньої ролі (файл у `docs/orchestration-run/`). Так контекст між ролями передається лише через handoff-документ, а не через спільну історію. Коміт у git робить координатор після рев'ю.
