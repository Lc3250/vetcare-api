# Онтологія застосунку (ПР4)

Онтологію виражено через типи нотаток, теги та папки vault (ПР2) і типізовані зв'язки.

## Типи сутностей
| Тип (`type`) | Папка | Що описує |
|--------------|-------|-----------|
| concept | Concepts/ | поняття предметної області (Власник, Тварина, Візит, Вакцинація, Ревакцинація, Довідник вакцин) |
| component | Components/ | модулі коду з шаром (`layer`: api, core, storage) |
| decision | Decisions/ | архітектурні рішення ADR |
| glossary | Glossary/ | терміни проєкту |
| moc | корінь | навігаційні нотатки |

## Типи зв'язків
Зв'язок записується в frontmatter нотатки-джерела як список назв: `depends_on: ["Назва А", "Назва Б"]`. Звичайні wiki-посилання в тексті лишаються для згадок і не мають семантики.

| Зв'язок | Від → до | Значення |
|---------|----------|----------|
| `depends_on` | component → component | модуль використовує інший модуль |
| `implements` | component → concept, decision, glossary | модуль реалізує поняття чи рішення |
| `supersedes` | decision → decision | нове рішення замінює старе |
| `belongs_to` | concept → concept | сутність належить іншій (Візит belongs_to Тварина) |

## Як записувати
Через MCP-інструмент `link_notes(title, relation, targets)`: він перевіряє тип зв'язку та існування цілей, ідемпотентний і зберігає зв'язки при подальшому `ingest_note`. Перевірку відповідності типам виконує `scripts/check_vault.py` у репозиторії vault.

## Приклади для VetCare
- `Модуль прострочених вакцинацій` depends_on `Модуль графіка ревакцинації`
- `Репозиторій SQLite` implements `ADR-001 Використання SQLite`
- `Візит` belongs_to `Тварина`
