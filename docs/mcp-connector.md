# MCP-конектор до бази знань (ПР3)

## Призначення
Сервер `mcp_server/server.py` – єдиний канал, яким агент читає й наповнює vault (окремий репозиторій `vetcare-knowledge-base`). Файлова система vault у робочій директорії IDE відсутня, тож в обхід інструментів агент до нього не дістанеться.

## Інструменти
| Інструмент | Напрям | Що робить |
|-----------|--------|-----------|
| `ingest_note(title, type, content, links, tags)` | у vault | створює або оновлює нотатку у відповідній папці, додає її в MOC, комітить і пушить |
| `get_note(title)` | з vault | повертає текст нотатки за назвою |
| `search_notes(query, limit)` | з vault | шукає нотатки за підрядком у назві чи тексті, повертає назву, шлях, уривок |

Схема `ingest_note`: `type` ∈ {concept, component, decision, glossary}; назва без `/ \ : * ? " < > |` та `..`; `links` – назви нотаток, які записуються як `[[...]]`.

## Цикл виклику ingest_note
1. Агент викликає інструмент з аргументами.
2. Сервер переходить на робочу гілку клону vault і виконує `git pull --rebase`.
3. Шукає нотатку за назвою; формує текст за конвенціями frontmatter (`type`, `created`, `tags`).
4. Якщо вміст збігається з наявним, повертає `unchanged` (і допушує невідправлені коміти). Інакше записує файл, додає посилання в розділ MOC, комітить і пушить.
5. Повертає `{status, path, pushed}`.

## Ідемпотентність
Повторний виклик з тими самими даними не створює файлів і комітів (`status: unchanged`). Дата `created` при оновленні зберігається. Покрито тестами `tests/test_vault_store.py`.

## Налаштування
Сервер зареєстровано у `.mcp.json` (Claude Code запускає його сам). Потрібні змінні середовища:
```
VETCARE_VAULT_PATH    шлях до окремого клону vetcare-knowledge-base (поза цим репозиторієм)
VETCARE_VAULT_BRANCH  робоча гілка vault (за замовчуванням main)
```
Залежності: `pip install -r requirements.txt` (потрібен `mcp` версії 2.x).

## Що перевірено
- 15 модульних і наскрізних тестів (`pytest`): створення, оновлення, ідемпотентність, push у віддалений репозиторій, окрема гілка, відхилення некоректних назв і типів, реєстрація в MOC, повторний push після збою, запуск сервера окремим процесом через stdio-клієнт.
- Три реальні виклики `ingest_note` через MCP-клієнт (`scripts/mcp_call.py`, протокол stdio, той самий, яким користується IDE) для завершених задач розробки. Результат – нотатки ADR-004, ADR-005, ADR-006 у гілці `praktychna-3` репозиторію vault; повторні виклики повернули `unchanged`, `check_vault.py` підтвердив: усі 24 нотатки досяжні з MOC.
- Під час перевірки знайдено й виправлено дві помилки (коміт `e665157`): нові нотатки не потрапляли в MOC, а після невдалого push повторний виклик повертав `unchanged` і не допушував коміт.

## Що не виконано в цьому середовищі
Виклик інструментів із самої агентної IDE (Claude Code, відкритий у репозиторії застосунку) і підключення GitHub MCP-сервера потребують середовища та токена студента. Кроки описано в [github-mcp.md](github-mcp.md).
