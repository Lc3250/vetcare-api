# Вимоги до agent harness для VetCare API

## Мета
Прискорити розробку VetCare API автономним агентом під інженерним наглядом студента й унеможливити небезпечні дії.

## Джерела даних (з'являтимуться в міру розробки)
| Джерело | Коли з'явиться |
|---------|----------------|
| `ЗАВДАННЯ.md`, `docs/app-requirements.md` | ПР1 |
| База знань (vault) – лише через MCP-конектор | ПР2–ПР3 |
| Код застосунку (`api/`, `core/`, `storage/`, `tests/`) | з ПР3 і далі |
| Історія git, pull request-и (GitHub MCP, лише читання) | ПР3 |
| Конвенції проєкту (стиль, формат комітів, `CLAUDE.md`) | ПР4–ПР5 |
| Вивід тестів і ruff | з першого модуля |

## Цільові задачі агента
1. **Каркас модуля.** Створення файлів нового модуля за шаблоном шарів. Економить рутину й зберігає єдину архітектуру.
2. **Генерація тестів.** pytest-тести для нової функції за шаблоном проєкту. Тести дають вимірюваний критерій «виконано правильно».
3. **Рев'ю коду.** Перевірка змін на відповідність конвенціям і guardrails. Знижує ризик порушення архітектури.
4. **Синхронізація документації та знань.** Оновлення нотаток vault і ADR після значущої зміни. Тримає базу знань актуальною для агента.

## Первинні guardrails (категорії дій)
| Рівень | Типи операцій |
|--------|---------------|
| Allow | Читання файлів, пошук по коду, запуск тестів і ruff, читання нотаток vault через MCP |
| Warn / require approval | Створення й зміна файлів коду, коміт у робочу гілку, запис у vault, встановлення залежностей |
| Block | Прямий пуш у `main`, видалення файлів і нотаток, `git push --force`, зміна історії git, запис секретів у репозиторій, прямий доступ до vault в обхід MCP |

Деталізація правил і hooks – у ПР4.
